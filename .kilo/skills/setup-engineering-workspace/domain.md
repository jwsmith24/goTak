# Domain-document conventions

Before architecture or terminology work, read the relevant root `CONTEXT.md`, or follow `CONTEXT-MAP.md` to the relevant context. Read applicable ADRs in `docs/adr/` or the context-local ADR directory. Missing files are not an error; `domain-modeling` creates them lazily after knowledge is resolved.

Use glossary terms consistently and surface contradictions with existing ADRs. A single-context repository uses root `CONTEXT.md` and `docs/adr/`. A multi-context repository uses root `CONTEXT-MAP.md`, per-context `CONTEXT.md` files, context-local ADRs, and root ADRs for system-wide decisions.
