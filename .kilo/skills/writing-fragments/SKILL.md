# Writing fragments

This is exploration. Invoke `grilling` to widen what could be written without imposing an outline, phases, or article structure.

A fragment is author-readable material that might survive: a sentence, claim, vignette, analogy, code example, half-thought, quoted line, observation cluster, confession, punchline, or a compact **leading word** that names the piece's central pattern. Preserve the user's voice. Never fabricate quotations, events, evidence, or attribution; label agent-proposed wording as a proposal.

## Establish append authorization

Capture the initial prompt as possible material. Before the first write:

1. confirm one absolute Markdown destination;
2. preview the format: one H1 working title, fragments in arrival order, `---` separators, no body headings or metadata;
3. warn before persisting sensitive, private, or identifying material;
4. obtain explicit **session-scoped authorization for append-only writes** to that destination.

After authorization, append agreed fragments throughout this session without asking for each append. Mention captures briefly without interrupting the interview.

Before every append, re-read the file. Preserve all user edits, reorderings, and deletions. If the file changed in a way that makes a safe append uncertain, stop and reconcile. Append atomically where possible; never replace the whole file.

Rewriting, merging, moving, or deleting any existing fragment is outside append authorization. Preview the exact change and obtain separate confirmation. Authorization ends when the destination changes or the session ends. Publishing, external actions, and Git operations are out of scope.
