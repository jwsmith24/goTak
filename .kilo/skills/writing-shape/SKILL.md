# Writing shape

Treat the raw-material file as a read-only quarry. Read it fully. Confirm a distinct article destination and the reader's prerequisite knowledge.

## Establish append authorization

Before writing, preview the destination, article format, and 2–3 materially different openings. For each opening, state its implied promise/angle, concepts it requires, and concepts it grounds. After the user chooses or combines one, obtain explicit **session-scoped authorization for append-only agreed blocks** to that article.

## Shape one block at a time

1. Re-read the article and account for user edits.
2. Track concepts grounded by prerequisites or prior blocks. A block may rely only on grounded concepts.
3. Offer 2–3 materially different reachable next moves when genuine alternatives exist. State what each move does, grounds, and unlocks. When only one move is structurally sensible, recommend it directly rather than manufacturing choices.
4. Choose the block form deliberately: prose for argument, list for parallel items, table for repeated fields, callout for a real aside, quotation when exact sourced wording matters, and code block for multiline illustrative or runnable code.
5. Write only the block the user agrees to; never draft ahead. Append it, then stop for the next decision.

Name gaps in the pile and ask for material or cut the move. Never invent evidence, anecdotes, facts, or quotations. End when the article fulfills its chosen promise, not when the pile is empty.

Re-read immediately before each append. Preserve concurrent edits and stop on conflict. Rewriting, moving, merging, or deleting existing blocks requires an exact preview and separate confirmation. The raw pile remains unchanged. Authorization ends with the session or destination change. Frontmatter, platform formatting, publishing, external actions, and Git operations are out of scope.
